## 1. 기준 정리와 v1.7의 5/20 → 4/20

[사전 고정 루브릭](v1.8.1-rubric.md)을 A/B/C에 공통 적용했다. FF=잘못된 사실, UC=근거 없는/잘못된 후보·필드, MF=필요 사실·필드 누락, MC=필요 후보 누락, EV=주장을 지지하지 못하는 근거. 같은 오류가 요약/상세/후보에 반복되면 surfaces를 묶고, 서로 다른 사실·약·필드는 분리한다. 아래 수치는 **관찰한 오류 단위**이며 임상 사실 전체의 재현율이나 오류율 분모가 아니다. 과거 보고서의 묶음 이슈 수를 원자 오류 수로 바꿔 부르지 않았다.

CRITICAL은 용량·약 선택/병용·중단·긴급 행동 조건을 바꿀 수 있는 오류, MAJOR는 중요 정보·행동·근거의 오류/누락이다. 문체·장문·중복 표현만의 MINOR는 전체 의미 판정을 뒤집지 않는다. 현재 약 두 제품을 하나의 약명으로 합치거나 원문에 없는 배타 선택을 부과한 UC는 모든 후보에서 CRITICAL로 분류했다. 검증 호출의 승인이나 ID 존재는 정답이 아니다.

v1.7의 차이는 **D07 한 건의 평가 누락을 교정한 것**이다. 원문은 “기존 약은 끊지 마세요”라고 명시했지만 저장 응답의 후보는 새 A/B 약뿐이었다. 보고서 문장에 지속 지시가 있다고 필요한 확인 후보까지 보존된 것은 아니다. 이름 미상 지속 후보가 필요하다. 나머지 19건의 전체 판정은 그대로다. 과거 파일을 덮어쓰지 않았고 [재판정 원장](../../eval-results/prompt-v1.7-quality-2026-10-09/v1.8.1-baseline-regrade.json)에 요청 SHA/근거/사유를 남겼다.

### 최소 구조 변경

- 역사적 `SemanticAnalysis`·v1.8 프롬프트/응답은 고정 보존. 새 `SemanticAnalysisV2`와 `semantic-facts-v2`/v1.8.1은 **opt-in 실험**이다.
- 근거 ID의 존재/중복, 내용 있는 근거와 단답 문맥을 구분한다. 같은 source/page, 인접한 서로 다른 알려진 화자의 실제 질문만 보완한다. `ADJACENT_QUESTION_CONTEXT`로 추가 ID를 기록한다. 답이나 위치를 발명하지 않는다.
- `MEDICATION` 보고 카테고리의 NONE/null, 약의 FUTURE+task=null, non-med FUTURE의 다른 kind를 표현할 수 있게 했다. 실제 약 객체가 있는 잘못된 카테고리는 `CATEGORY_FROM_MEDICATION_OBJECT`로 드러내고 정규화한다. 약 역할/용량은 바꾸지 않는다.
- 검사 결과는 전체 원시 facts, 정규화, repairs, 모든 실패 factId/path/code를 보존한다. **부분 성공 API는 만들지 않았고 하나라도 실패하면 전체 적용을 차단**한다. 실패 항목을 조용히 삭제하지 않는다.
- 성공 후보도 모두 `EXPERIMENTAL_SEMANTIC_REVIEW` → `NEEDS_REVIEW`. 약 확인, 미상 날짜/시각의 적용 단계 필수값 검증은 기존 정책 그대로다.
- r1 A/B 응답에서 발견한 ‘평서+질문이 한 발화에 있음’, ‘약 객체와 kind 중복’ 과잉 거절을 r2로 고쳤다. 프롬프트/스키마/요청은 바꾸지 않고 저장 응답을 공통 r2로 재생했다. 최초 record status는 덮어쓰지 않는다. **새 최종 입력 확보 후에는 r2를 수정하지 않았다.**

실제 경로: `OpenAiProcessingAdapter.analysisRequest()` → 동일 Responses 요청 → `parseAnalysis()` → `SemanticAnalysisV2` → 기존 `UtteranceEvidence` 원문/위치 연결 → `AnalysisOutputValidator`. eval은 이 경로를 쓰되 Spring/DB/ReviewService/일정 저장을 띄우지 않는다. 실행되지 않는 프롬프트 파일만 추가한 것이 아니다.

## 3. 통제 조건·모델 선정

OpenAI Docs와 계정의 읽기 전용 `/v1/models`로 확인했다. 사용 가능한 상위 후보에 `gpt-6.1-sol`, `gpt-6-astra` 등이 있었고, 이 예산에서는 **gpt-6.1-sol**을 골랐다. 의학적 우월성이 확인됐다는 뜻이 아니다. [Sol 공식 모델/요금](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Mini 공식 모델/요금](https://developers.openai.com/api/docs/models/gpt-5.4-mini).

| 비교군 | 모델·입력 |
| --- | --- |
| A | `gpt-5.4-mini-2026-03-17` + 수정 v1.8.1, 선별 6 |
| B | `gpt-6.1-sol` + **A와 동일한 프롬프트/스키마/원문/설정**, 선별 6 뒤 기존 전체 20으로 확장 |
| C | B 모델 + **완전한 동일 원문과 정확한 B raw 응답** + 고정 검증/수정 지시. 같은 스키마의 완전한 대체 결과 생성 |

A/B 요청은 model 필드만 다른지 자동 테스트했다. 공통 `reasoning.effort=low`, `service_tier=default`, `max_output_tokens=12000`, `store=false`. Sol은 none을 지원하지 않아 low로 맞췄다. 역사적 v1.7/v1.8의 mini reasoning 미지정과는 다르므로, 역사적 결과와 새 A의 차이를 **순수 프롬프트나 파서 효과로 단정하지 않는다**. A→B만 모델 변경 효과, B→C만 검증 단계 추가 효과다.

실호출 중 가이드라인은0.6.0, 종료 후 평가 이력을 반영한 문서는0.6.1이다. 실행 프롬프트1.8.1·스키마·파서·검증 지시·루브릭 SHA와 원본 스냅샷은 `v1.8.1-plan.json`/`v1.8.1-plan-r2.json`에 보존했다.

선별 6건은 D01/D11/H01/day3/05/day3/08/day1/02로, 정정 용량·문서 처방 역할·조건부 행동·대안 약·기간/시각·질문/답을 포함한다. 원문부터 평가 기준까지 모두 동일하게 적용했다. 정확한 canonical 전체 요청 SHA로만 재사용하며 실패 캐시도 재호출하지 않는다. 과거 v1.6/v1.7 응답을 새 후보의 실행 결과로 사용하지 않았다.
