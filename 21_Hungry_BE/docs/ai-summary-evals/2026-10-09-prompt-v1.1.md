## 실패 분류와 조정

1. 간접화법 반복: 결과와 행동을 직접 쓰는 규칙 및 대표 변환을 추가했다.
2. 후보 누락·잘못된 복약 일정: 보고서와 item 추출을 분리하고, `occurredOn`을 약 시작일로 사용하지 않으며 명시 시각 없이는 `schedulePlans=[]`을 사용하도록 보완했다.
3. 자가진단/조건부 증상의 symptoms 오분류: 실제 경험한 증상만 허용하도록 보완했다.
4. 정정 quote 변형: root와 item evidence 각각 exact substring을 요구하고 스크립트 자동 검사를 추가했다.
5. 의미상 evidence index 불일치: 추상 규칙과 명시 예시 모두 안정적으로 해결하지 못했다. 현재 서버 검증은 exact substring과 index 범위는 거부하지만 주장-근거 의미 일치까지 판정하지 못한다.
6. 조건부 TASK 추출 일관성: 조건은 summary/details에 보존됐고 생성된 후보는 `isConditional=true`였지만, D01·H02에서 TASK 후보의 존재 여부가 재실행마다 달랐다. 잘못된 자동 일정은 생성되지 않지만 조건부 후보 recall은 별도 개선이 필요하다.

## 대표 비교

입력: `의사: 원인은 아직 확실하지 않아요. 처방약 드시고 쉬세요. 사흘 뒤에도 아프면 다시 오세요.`

- v1.0: `의사가 원인은 아직 확실하지 않다고 했고, 처방약 복용 및 휴식을 안내했으며, 3일 뒤에도 아프면 다시 오라고 했습니다.`
- v1.1: `원인은 아직 확실하지 않음. 처방약 복용과 휴식. 사흘 뒤에도 아프면 재방문.`

별도 평가 입력 H01의 v1.1 결과: `검사 전이라 위염으로 단정할 단계는 아님. 가상 C약 저녁 1정씩 4일 복용. 검사 양성이면 예약일 전에 연락 예정.`

## 채택 판단과 남은 문제

프롬프트 v1.1은 핵심 요약 정확성과 가족용 보고서 문체가 v1.0보다 나아 운영 경로에 반영했다. 다만 D04의 의미상 evidence index 불일치는 해결되지 않았으므로 근거 정확성 평가를 통과했다고 보지 않는다. 조건부 TASK 후보 추출도 재실행 간 일관성을 확인하지 못했다. 배포 전후 모니터링에서 같은 패턴을 수집하고, 다음 개선에서는 detail별 근거를 모델 인덱스에만 의존하지 않고 서버에서 검증·재연결할 수 있는 범위와 후보 recall 평가를 별도 설계해야 한다. 의료진 검토와 실제 의료 데이터 평가는 수행하지 않았다.
