## 2. 구현 순서

### 작업 1 — 현재 데이터 검사와 추가 migration

우선순위 P0, 선행 없음.

- 최신 main/작업 브랜치·미커밋 변경·Flyway 이력을 먼저 확인한다. 문서 버전과 실제 코드를 대조한다.
- DB v1.3의30개 목표 테이블과 기존 스키마 차이를 추가 migration으로 구현한다. 제공한 target SQL을 운영 DB에 직접 실행하지 않는다.
- account_role·부모 nullable 이름·전화번호 정규화 유일성·부모 최초 프로필·PENDING 멤버·단일 현재 관계·priority1/2를 추가한다.
- group_join_request, handoff_response, creation_origin, document_type 추가.
- 기존 데이터의 전화번호·계정 역할·복수 공동체·부모 출생연도·PICKUP·문서 분류를 점검한다. 모호한 값은 보고하고 무단 추정/삭제하지 않는다.
- notification_preference는 보존하지만 새 worker 의존성 제거. 예전 pending digest도 새 정책에 맞춰 처리한다.

완료 기준: 기존 데이터 보존, 격리 PostgreSQL migration/rollback 계획,30개 목표 구조 및 제약 검증. 본 문서의 PGlite17검사는 실제 migration 검증을 대신하지 않는다.
